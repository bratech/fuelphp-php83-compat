# Compatibility release 1.0.3

This release makes `oil console` leave its input loop when standard input ends. `Cli::input()` returns `false` at end of input; the original loop treated that as an empty line and kept prompting, so a console whose terminal had closed used a full CPU core indefinitely. Empty lines, `quit` and every other input are unchanged.

## Upgrading

With the old compatibility package still installed, stop application processes and reverse its patches using its own tool. Then update to `bratech/fuelphp-php83-compat:1.0.3`, apply the new patches and run `check` and application tests. See the [1.0.2 to 1.0.3 upgrade commands](../OPERATIONS.md#upgrading-from-102-to-103).

The release is a cumulative patch set, not a patch to apply over 1.0.2. Existing tags are unchanged. FuelPHP and upstream dependency versions are unchanged. Only `fuel/oil` `classes/console.php` changes; the number of patched files stays the same.

## Verification and limits

- Applying the new `fuel-oil.patch` to the recorded original source produced the manifest's patched hash, and the result passes a PHP syntax check.
- The distribution suites passed on PHP 7.4.34 and 8.3.35: Project 38 cases, Transaction 18 cases and the CLI scenarios.
- This release has no new automated test of the console loop itself. Other packages' patches are unchanged and were not retested.
