# Compatibility release 1.0.1

This release fixes failure cleanup in the FuelPHP 1.8.2 compatibility patch set. It does not change FuelPHP's upstream version or the fixed dependency versions. PHP 7.4/8.3 and ICU/ext-intl remain required as documented.

- ORM rolls back/unfreezes on Error paths; nested rollback semantics are unchanged.
- Request/Presenter and View restore caller context after the tested failures. Presenter accepts a request without a module.
- View/Smarty preserve caller buffers and release filtered objects; cleanup failures do not replace the original rendering failure.
- SMTP releases failed connections and preserves the original sending error even if QUIT fails.

## Upgrading

**With 1.0.0 still installed, reverse using the 1.0.0 tool before updating Composer to 1.0.1.** Keep the application stopped until the new apply/check and application tests succeed. The new tool rejects old patched hashes; this is not an incremental patch to stack on 1.0.0.

Use the GitHub VCS repository and require `bratech/fuelphp-php83-compat` at `1.0.1`. Follow the [update commands](https://github.com/bratech/fuelphp-php83-compat/blob/v1.0.1/docs/OPERATIONS.md#upgrading-from-100-to-101), [Japanese guide](https://github.com/bratech/fuelphp-php83-compat/blob/v1.0.1/docs/README.ja.md) and [behavior changes](https://github.com/bratech/fuelphp-php83-compat/blob/v1.0.1/docs/BEHAVIOR_CHANGES.md).

## Verification and limitations

The corrected scope passed 218 checks across PHP 7.4 and 8.3. The six PHP/database configurations passed twice each (12 full regression runs). The cumulative 34-file patch also passed source-hash and application/reversal checks. Four local Composer configurations passed actual 1.0.0 reversal, update to the new package, clean installation and associated regression tests before publication.

PDO profiler cleanup, final-handler failures with an unusable log destination and PHP 7.4 shutdown handling remain outside this fix. Custom cleanup failures and non-removable buffers cannot guarantee complete state restoration. The recorded phpseclib audit finding remains; this is not a new audit or a package-wide safety guarantee. See [verification scope](https://github.com/bratech/fuelphp-php83-compat/blob/v1.0.1/docs/VERIFICATION.md).
